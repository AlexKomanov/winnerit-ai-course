מה זה API?

הדרך שבה המסך מדבר עם השרת. כשלוחצים "שמור", המסך שולח בקשה, והשרת מחזיר תשובה.

המסך (UI)

מה שהמשתמש רואה ולוחץ עליו

ה-API

מקבל בקשות מהמסך ומחזיר תשובות

מסד הנתונים

המקום שבו המידע נשמר

כמו מלצר במסעדה. אנחנו מזמינים, המלצר מעביר למטבח ומחזיר את המנה. ה-API הוא המלצר.

בקשה ותשובה

בבדיקת API אנחנו שולחים את הבקשה בעצמנו, בלי מסך, ובודקים מה חזר.

request · הבקשהPOST /api/tasks Content-Type: application/json { "title": "Buy milk" }
→
response · התשובה201 Created { "id": 42, "title": "Buy milk", "done": false }
קוד הסטטוס201 = נוצר. 404 = לא נמצא. 500 = השרת נכשל.
תוכן התשובההאם חזרו השדות הנכונים, עם הערכים הנכונים?
קלט שגוימה קורה כששולחים משימה בלי כותרת? נצפה לשגיאה ברורה.

למה לא רק דרך המסך?

בדיקה דרך המסך בודקת הכל ביחד. בדיקת API בודקת את השרת לבד, ולכן יש לה שלושה יתרונות.

מהירה

לא פותחים דפדפן ולא מחכים שדף ייטען. שולחים בקשה ומקבלים תשובה.

יציבה

כפתור שזז או שינה צבע לא שובר את הבדיקה, כי היא לא נוגעת במסך.

מדויקת

כשהבדיקה נכשלת, יודעים שהבעיה בשרת ולא בעיצוב של המסך.

בדיקת API ראשונה

  • 1request הוא כלי מובנה של Playwright, ששולח בקשות בלי לפתוח דפדפן.
  • 2שולחים בקשת POST עם הנתונים של המשימה החדשה.
  • 3בודקים שהסטטוס שחזר הוא 201.
  • 4בודקים שהתשובה מכילה את הכותרת ששלחנו.
import { test, expect } from '@playwright/test';

test('creates a new task', async ({ request }) => {1
  const response = await request.post('/api/tasks', {2
    data: { title: 'Buy milk' }
  });

  expect(response.status()).toBe(201);3

  const task = await response.json();
  expect(task.title).toBe('Buy milk');4
});

מכינים את הסביבה

1install

מתקינים Playwright

פקודה אחת בתיקיית הפרויקט. היא מתקינה את Playwright ויוצרת קובץ הגדרות.

>_npm init playwright@latest
2config

מגדירים כתובת בסיס

בקובץ playwright.config.ts נכתוב את כתובת האפליקציה. כך בבדיקות מספיק לכתוב /api/tasks.

use: { baseURL: 'http://localhost:3000' }
3run

מריצים

מריצים את כל הבדיקות. את הדוח המפורט פותחים עם npx playwright show-report.

>_npx playwright test

API + UI ביחד

אפשר לשלב את שניהם באותה בדיקה: ה-API עושה את ההכנות מהר, והמסך מראה מה המשתמש באמת רואה.

מכינים נתונים ב-API

יוצרים משימה בבקשה אחת, בלי למלא טופס

בודקים במסך

פותחים את הדף ורואים שהמשימה מופיעה

מנקים ב-API

מוחקים את המשימה, כדי שהבדיקה הבאה תתחיל נקי

וגם בכיוון ההפוך: ממלאים טופס במסך, ואז שואלים את ה-API אם המשימה באמת נשמרה.

הדוגמה בקוד

  • 1מבקשים גם page (הדפדפן) וגם request (ה-API).
  • 2יוצרים משימה דרך ה-API.
  • 3פותחים את המסך ובודקים שהמשימה מופיעה.
  • 4מוחקים את המשימה דרך ה-API.
test('task created by API shows on screen',
  async ({ page, request }) => {1

  const res = await request.post('/api/tasks', {2
    data: { title: 'Buy milk' }
  });
  const task = await res.json();

  await page.goto('/tasks');3
  await expect(page.getByText('Buy milk')).toBeVisible();

  await request.delete(`/api/tasks/${task.id}`);4
});

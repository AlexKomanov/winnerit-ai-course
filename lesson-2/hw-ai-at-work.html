מתקינים Plugins

חובה1 · Plugins2 · Skill3 · Marketplace4 · Subagent5 · PRD6 · Test cases
1open

פותחים את החנות

ב-Claude Code נקליד /plugin, נעבור ל-Discover ונחפש לפי שם.

/plugin → Discover → search
2install

מתקינים שניים

נתקין את שניהם ב-scope של User, כדי שיהיו זמינים בכל הפרויקטים.

>/plugin install skill-creator@claude-plugins-official
>/plugin install superpowers@claude-plugins-official
3reload

טוענים ובודקים

נטען מחדש, ונוודא בלשונית Installed ששניהם שם.

>/reload-plugins

Skill כללי משלנו

חובה1 · Plugins2 · Skill3 · Marketplace4 · Subagent5 · PRD6 · Test cases
1choose

בוחרים משימה

משימה מהעבודה שחוזרת כל שבוע ואינה קוד: עדכון שבועי למנהל, סיכום פגישה, תשובה למיילים בסגנון שלנו, סיכום חדשות בתחום.

2write

כותבים

מבקשים מ-Claude Code, עם skill-creator או בלעדיו. נקרא את SKILL.md שנוצר ונוודא שה-description כולל Use when.

>Help me create a personal skill that turns my task list into a weekly update for my manager
3test

בודקים פעמיים

פעם דרך הפקודה עם השם, ופעם במילים רגילות. אם ה-Skill לא הופעל לבד — נשפר את התיאור ונבדוק שוב.

Marketplace משלנו

חובה1 · Plugins2 · Skill3 · Marketplace4 · Subagent5 · PRD6 · Test cases
1build

בונים ובודקים

repository בשם my-ai-toolkit עם Plugin אחד שמכיל את ה-Skill שלנו. בסוף מריצים בדיקה:

>_claude plugin validate .
2push

מעלים ל-GitHub

repository ציבורי. השם של ה-Plugin צריך להיות זהה ב-marketplace.json וב-plugin.json.

3install

מתקינים מ-GitHub

מוסיפים את ה-Marketplace, מתקינים, ומוחקים את העותק מ-~/.claude/skills/. מנסים: /plugin-name:skill-name

>/plugin marketplace add OWNER/my-ai-toolkit

Subagent לפיצ׳רים

רשות1 · Plugins2 · Skill3 · Marketplace4 · Subagent5 · PRD6 · Test cases
1create

מבקשים מ-Claude

נתאר את הסוכן. הוא יישמר ב-~/.claude/agents/ ויהיה זמין בכל הפרויקטים.

>Create a personal feature-writer subagent in ~/.claude/agents/ that pulls the latest code, asks which feature we want, scans the project, plans with superpowers, writes the code, shows us the changes, and commits and pushes only after we approve.
2review

בודקים את הקובץ

נפתח את feature-writer.md ונוודא שהשלב של "מראה שינויים ומחכה לאישור" באמת כתוב שם.

3use

מוסיפים פיצ׳ר

בתיקייה של הפרויקט מ-Lovable נבקש פיצ׳ר אחד קטן, נבדוק את השינויים ונאשר. Lovable יקבל את השינוי דרך GitHub.

>Use the feature-writer agent to add a dark mode toggle

PRD לאפליקציה שלנו

רשות1 · Plugins2 · Skill3 · Marketplace4 · Subagent5 · PRD6 · Test cases
1connect

מוודאים חיבור

ב-Claude Desktop נבדוק ש-playwright מופיע ב-Developer. אם לא — נחבר כמו במצגת Playwright MCP.

Settings → Developer → playwright ✓
2explore

מריצים את הפרומפט

נדביק את פרומפט ה-PRD מהמצגת, עם ה-URL של האפליקציה שפרסמנו ב-Lovable, ונחכה שהסיור יסתיים.

3save

שומרים

נעלה את קובץ ה-PRD ל-Google Drive, כדי שנוכל לחבר אותו ל-Skill בשלב הבא.

Test cases מה-PRD

רשות1 · Plugins2 · Skill3 · Marketplace4 · Subagent5 · PRD6 · Test cases
1skill

Skill לבדיקות

ב-Gemini ניצור Skill כמו במצגת Test Generator — עם שם ו-description שמתאימים לאפליקציה שלנו.

Customize → Skills → Create → Create manually
2prd

מחברים את ה-PRD

נוסיף את ה-PRD מ-Google Drive כקובץ ידע, ונדביק את ההוראות מהמצגת.

Add → Google Drive → PRD → Create
3generate

מייצרים בדיקות

נבחר שני פיצ׳רים ונבקש test cases לכל אחד. נבדוק שהשמות והמסכים באמת מופיעים באפליקציה.

/Create test cases for the login flow

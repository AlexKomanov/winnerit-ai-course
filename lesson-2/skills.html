# Email reply

1. Read the email we pasted and find what the sender asks for.
2. Write the reply in the same language as the email.
3. Keep it short: 3-6 sentences, polite and direct.
4. Never promise dates or prices. Write [CHECK] there.
5. End with: Best regards, [YOUR NAME]
6. Return only the reply text, ready to copy into our email app.

נריץ /reload-skills ונבקש פיצ׳ר קטן, למשל כפתור חדש בדף. נוודא שנפתח branch חדש, שיש commit אחד, ושקיבלנו כותרת והסבר ל-PR. אחר כך נבקש תיקון קטן, וה-commit צריך להישאר אחד.

הפרומפט: אנגלית או עברית

תרגיל בכיתה נעתיק אחד מהשניים ונבקש מ-Claude Code. אותה בקשה, בשתי שפות

בעברית

>צור Skill של פרויקט בשם new-feature. למה: כל פיצ׳ר חדש צריך להיות מבודד וקל לבדיקה. מה הוא עושה: מלווה פיצ׳ר חדש מ-branch ועד PR. כללים: - קודם מעדכנים את main: git checkout main, git pull - פותחים ממנו branch חדש ועובדים רק עליו - commit אחד בלבד. שינויים נוספים נכנסים אליו עם git commit --amend - דוחפים את ה-branch. אחרי amend צריך: git push --force-with-lease - בסוף נותנים כותרת והסבר קצרים ל-PR - משתמשים רק בפקודות git קלאסיות מתי להפעיל: בכל פעם שמבקשים פיצ׳ר חדש.

באנגלית

>Create a project skill named new-feature. Why: every new feature should be isolated and easy to review. What it does: guides a new feature from branch to pull request. Rules: - Update main first: git checkout main, git pull - Create a new branch from it and work only there - One commit only. Later changes: git commit --amend - Push the branch (after an amend: git push --force-with-lease) - End with a pull request title and a short explanation - Use only classic git commands, nothing else When to use: whenever we ask for a new feature.
